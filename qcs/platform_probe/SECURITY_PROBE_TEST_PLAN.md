# Security Probe — Test Plan (TASK 03)

แผนทดสอบนี้ใช้ `security_probe_main.lua` บน IQ Option จริงเพื่อตอบ 6 คำถาม:

1. ข้อมูล M5 เปลี่ยนเมื่อใด (T1)
2. ข้อมูล M15 เปลี่ยนเมื่อใด (T2)
3. Index `[0]` และ `[1]` มีความหมายอย่างไร (T3)
4. แท่ง HTF ที่ปิดแล้วมีความเสถียรหรือไม่ (T4)
5. Historical Data เปลี่ยนย้อนหลังหรือไม่ (T5)
6. M5/M15 มีเวลาเปิดและปิดตรงกับกรอบเวลาจริงหรือไม่ (T6)

T0 คือการตรวจว่าสคริปต์โหลดได้และ API ไหนใช้ได้ ต้องทำก่อน

> ทุกผลต้องมาจาก IQ Option จริง (บัญชี Demo) ห้ามใช้ผลจาก mock หรือข้อมูลจำลองแทน
> ถ้าผลไม่ตรงกับที่คาด **ให้บันทึกตามจริง** อย่าแก้โค้ดเพื่อให้ผ่าน

## T0 — โหลดสคริปต์และตรวจ API

**ขั้นตอน**
1. ติดตั้ง Probe ตาม README §1
2. ถ้ามี error ตอน Save หรือ Add to chart → ถ่ายภาพข้อความ error ทั้งหมด จบ T0 แล้วส่งผลกลับ (ไม่ต้องทำต่อ)
3. ตั้ง View = 3 รอให้กราฟโหลดเสร็จ เลื่อน crosshair ไปที่แท่งล่าสุด ถ่ายภาพ
4. จดค่า `ST sec 1m`, `ST sec 5m`, `ST sec 15m`, `ST EMA M5`, `ST EMA M15`, `ST RSI M5`, `ST RSI M15`
5. ดูว่ามี marker `NOT M1`, `M5 ERR`, `M5 UNSUP`, `M15 ERR`, `M15 UNSUP`, `EMA5 X` ด้านบนหรือไม่
6. ตรวจว่า legend แสดงตัวเลขของทุกเส้นหรือไม่ (ถ้าไม่แสดง จดไว้)
7. ตั้ง `Print log = 1` ชั่วคราว หาว่า log ไปแสดงที่ไหน ถ่ายภาพ แล้วตั้งกลับเป็น 0
8. เลื่อนกราฟไปซ้ายสุด ดูว่าแท่งแรก ๆ ที่สถานะ M5/M15 เปลี่ยนจาก 0 เป็น 1 อยู่ตรงไหน (warm-up)

**ผลที่คาด**: `ST sec 5m` และ `ST sec 15m` = 1 บนแท่งล่าสุด
**บันทึก**: ค่าสถานะทั้ง 7 ตัว, marker ที่เห็น, ข้อความ error (ถ้ามี), ตำแหน่ง log, legend อ่านได้หรือไม่

| ผล | ความหมาย |
|---|---|
| `ST sec 5m = -2` หรือ marker `M5 UNSUP` | ไม่มี `security` หรือไม่มี field ที่ต้องการ → MTF ผ่าน `security()` ใช้ไม่ได้ |
| `ST sec 5m = -1` | `security(current_ticker_id,"5m")` error → ส่งข้อความ log (`Print log = 1`) กลับมา |
| `ST sec 5m = 0` ทุกแท่ง | เรียกได้แต่ไม่มีข้อมูล |
| `ST EMA M5 = -2` | ไม่มีฟังก์ชัน `ema` ให้เรียก |
| `ST EMA M5 = -1` | มี `ema` แต่ใช้กับ series จาก `security()` ไม่ได้ |

## T3 — ความหมายของ Index `[0]` และ `[1]`

**ขั้นตอน** (View 2 และ View 5)
1. View 2: เลื่อน crosshair ไปทีละแท่ง M1 ย้อนหลังอย่างน้อย 15 แท่ง (ครอบคลุม 3 แท่ง M5 และ 1 รอบ M15) จดค่า `M5 step`, `M15 step`, `M5 phase`, `M15 phase` ทุกแท่ง
2. View 5: ถ่ายภาพ 2 แท่งติดกันที่อยู่ในแท่ง M5 เดียวกัน และ 2 แท่งที่คร่อมการขึ้นแท่ง M5 ใหม่
3. View 1: ที่แท่ง M1 แรกของ M5 ใหม่ (`N5`) จด `M5 Close[1]` แล้วเปลี่ยนกราฟเป็น Timeframe 5 นาทีชั่วคราว อ่าน close ของแท่ง M5 ที่เพิ่งปิด เทียบกัน แล้วเปลี่ยนกลับเป็น M1

**ตีความ**

| สิ่งที่เห็น | ความหมาย |
|---|---|
| `M5 step = 0` เกือบทุกแท่ง และ = 300 เฉพาะแท่ง `N5` | series จาก `security()` **เรียงตามแท่ง M1 ของกราฟ**: `[1]` = ค่าของ M5 ณ แท่ง M1 ก่อนหน้า **ไม่ใช่**แท่ง M5 ที่ปิดแล้ว (ยกเว้นบนแท่ง `N5`) |
| `M5 step = 300` ทุกแท่ง | `[1]` = **แท่ง M5 ก่อนหน้า** โดยตรง |
| `M5 Close[1]` บนแท่ง `N5` = close ของแท่ง M5 ที่เพิ่งปิดบนกราฟ M5 จริง | ค่าแท่งที่ปิดแล้วอ่านได้ถูกต้องอย่างน้อย ณ จุดนั้น |
| ค่าอื่น (เช่น step ไม่คงที่, ติดลบ) | บันทึกตามจริงและส่งภาพกลับ |

ทำแบบเดียวกันสำหรับ M15 (`step` 0/900, เทียบกับกราฟ 15 นาที)

## T4 — แท่ง HTF ที่ปิดแล้วเสถียรหรือไม่ (Live)

**ขั้นตอน** (View 1 และ View 3) — ทำระหว่าง T1/T2
1. หลังขึ้นแท่ง M5 ใหม่ จด `M5 Close[1]` ทุกครั้งที่ถ่ายภาพจนกว่าจะถึงแท่ง M5 ถัดไป (≈ 5 นาที, อย่างน้อย 5 ภาพ ภาพละแท่ง M1)
2. View 3: ดู `F M5 C1 changed` / marker `C1CHG5` บนแท่ง M1 ทั้งหมดในช่วงนั้น
3. ระหว่างแท่ง M1 ที่กำลังก่อตัว ดูว่า `M5 Close[1]` ขยับตาม tick หรือไม่ (ถ่าย 2–3 ภาพในแท่งเดียวกัน)
4. ทำซ้ำสำหรับ M15 ด้วย `M15 Close[1]` และ `C1CHG15`

**ตีความ**

| ผล T3 | ผล T4 | ข้อสรุป |
|---|---|---|
| `[1]` = แท่ง HTF ก่อนหน้า (step 300) | `M5 Close[1]` คงที่ตลอด 5 นาที, `C1CHG5` ไม่เกิด, ไม่ขยับตาม tick | **แท่ง M5 ที่ปิดแล้วเสถียร (Live)** |
| `[1]` = แท่ง HTF ก่อนหน้า | `M5 Close[1]` เปลี่ยนระหว่างแท่ง หรือ `C1CHG5` เกิด | **ไม่เสถียร** ใช้ทำ MTF ไม่ได้จนกว่าจะรู้สาเหตุ |
| `[1]` = แท่ง M1 ก่อนหน้า (step 0) | `C1CHG5` เกิดเกือบทุกแท่ง | **เป็นเรื่องปกติของการเรียงตาม M1** ไม่ใช่ repaint; ค่าแท่ง M5 ที่ปิดแล้วต้องอ่านจากแท่ง `N5` (หรือวิธีอื่นที่ต้องออกแบบใน Task ถัดไป) ให้ใช้ขั้นตอน T3 ข้อ 3 ยืนยันแทน |

## T5 — ข้อมูลย้อนหลังเปลี่ยน (Repaint ย้อนหลัง) หรือไม่

ทดสอบนี้เทียบ "ค่าที่เห็นตอน real-time" กับ "ค่าที่โหลดใหม่จาก history" บนแท่งเดียวกัน

**ขั้นตอน**
1. ระหว่าง T1–T4 จะมีภาพของแท่ง M1 อย่างน้อย 15 แท่งที่ถ่ายตอน real-time (View 1 และ View 3) พร้อมเวลา
2. หลังจบ T1–T4 อย่างน้อย 5 นาที: **reload หน้า IQ Option** (หรือลบ Probe ออกแล้วเพิ่มใหม่) เพื่อให้ Probe คำนวณใหม่จาก history
3. เลื่อน crosshair ไปที่แท่ง M1 เดิมทุกแท่งที่ถ่ายไว้ (ดูจากเวลาบนแกนกราฟ) ถ่ายภาพ View 1 และ View 3 อีกครั้ง
4. เทียบค่าทีละแท่ง: `M5 Close[0]`, `M5 Close[1]`, `M15 Close[0]`, `M15 Close[1]`, `EMA on M5`, `EMA on M15` และ flags
5. View 3 บน history: ดูรูปแบบของ `F M5 C0=Chart` ในแต่ละช่วง 5 นาที

**ตีความ**

| สิ่งที่เห็น | ข้อสรุป |
|---|---|
| ทุกค่าหลัง reload = ค่าที่เห็นตอน real-time (ภาพสุดท้ายของแต่ละแท่ง M1) | ไม่มี repaint ย้อนหลังสำหรับค่านั้น |
| Live: `F M5 C0=Chart = 1` ทุกแท่ง แต่ history: `= 1` **เฉพาะแท่ง M1 สุดท้ายของแต่ละ M5** (phase = 240) | history ระบายค่า close **สุดท้าย**ของ M5 ลงทุกแท่ง M1 ในช่วงนั้น → `[0]` **repaint ย้อนหลัง** ห้ามใช้ `[0]` ของ HTF ตัดสินใจ |
| `M5 Close[1]` หลัง reload ≠ ตอน live บนแท่งเดียวกัน | **closed HTF repaint** → ห้ามใช้ MTF ผ่าน `security()` แบบนี้ |
| `F M5 lookahead = 1` หรือ marker `LA5` บนแท่งใดก็ตาม (live หรือ history) | แท่ง M1 เห็นข้อมูลแท่ง M5 ในอนาคต → **ไม่ผ่าน** |
| EMA บน M5/M15 หลัง reload ≠ ตอน live | EMA ได้รับผลจาก repaint ของ series ต้นทาง |

ทำ T5 ซ้ำอย่างน้อย 2 ครั้งในวันต่างกันถ้าทำได้

## T6 — เวลาเปิด/ปิดของ M5/M15 ตรงกับกรอบเวลาจริงหรือไม่

**ขั้นตอน** (View 2 และ View 5)
1. View 5: เลือก 3 แท่ง M1 ถ่ายภาพ จด `Chart open_time`, `Chart close_time`, `M5 open_time[0]`, `M5 close_time[0]`, `M15 open_time[0]`, `M15 close_time[0]`
2. แปลง timestamp เป็นวันเวลาด้วยเครื่องมือแปลง UNIX time ใด ๆ (เช่น คำสั่ง `date -d @<ตัวเลข>` หรือเว็บแปลง epoch) ทั้งแบบ UTC และเวลาไทย จดผล
3. เทียบกับเวลาบนแกนกราฟของแท่งเดียวกัน
4. View 2: ไล่ดู 15 แท่งล่าสุด จด `M5 dur`, `M5 ot0 mod 300`, `M15 dur`, `M15 ot0 mod 900`, `M5 phase`, `M15 phase`
5. เปลี่ยนกราฟเป็น 5 นาทีชั่วคราว ดูว่าแท่ง M5 บนกราฟจริงเริ่มเวลาเดียวกับ `M5 open_time[0]` หรือไม่ ทำแบบเดียวกันกับ 15 นาที

**ผลที่คาดถ้าถูกต้อง**

| ค่า | คาด |
|---|---|
| หน่วยของ timestamp | วินาที (ตัวเลข 10 หลัก) ถ้า 13 หลัก = มิลลิวินาที (ค่าใน View 2 จะคูณ 1000) |
| `M5 ot0 mod 300` / `M15 ot0 mod 900` | 0 ทุกแท่ง |
| `M5 dur` / `M15 dur` | 300 / 900 (หรือ 299 / 899) คงที่ |
| `M5 phase` | 0, 60, 120, 180, 240 ไล่ตามแท่ง M1 แล้ววนใหม่ที่ `N5` |
| `M15 phase` | 0, 60, ..., 840 |
| `phase` ติดลบ | **ไม่ผ่าน** (lookahead) |
| open_time แปลงแล้ว | ตรงกับเวลาบนแกนกราฟ (ระบุ timezone ที่ IQ Option ใช้แสดง) |

บันทึกพิเศษ: ถ้ามีแท่ง M1 หายหรือตลาดปิดในช่วงทดสอบ ให้ดูว่า phase/step ผิดรูปแบบตรงไหน

## 7. เกณฑ์ผ่านก่อนอนุญาตให้ออกแบบ MTF (สำหรับ Owner ตัดสิน)

MTF ผ่าน `security()` จะใช้ได้ใน V2 ก็ต่อเมื่อ **ทุกข้อ** ต่อไปนี้ยืนยันจากผลจริง:

1. T0: `ST sec 5m = 1` และ `ST sec 15m = 1` หลัง warm-up และไม่มี marker ERROR/UNSUPPORTED
2. T6: mod = 0, dur คงที่, open_time ตรงกับกราฟ M5/M15 จริง, ไม่มี phase ติดลบ
3. T5: ไม่พบ `LA5`/`LA15` เลย
4. T3 + T4: ระบุได้แน่นอนว่าค่า "แท่ง HTF ที่ปิดแล้ว" อ่านจากอะไร และค่านั้น **ไม่เปลี่ยนระหว่าง tick, ไม่เปลี่ยนจนถึงแท่ง HTF ถัดไป, และเท่ากับ close บนกราฟ M5/M15 จริง**
5. T5: ค่าแท่ง HTF ที่ปิดแล้วหลัง reload = ค่าตอน live ทุกแท่งที่บันทึก
6. ถ้าจะใช้ EMA/RSI บน HTF: T0 ต้องได้ `ST EMA = 1` และ T5 ต้องไม่พบ EMA เปลี่ยนหลัง reload; และต้องรู้จาก T3 ว่า EMA คำนวณต่อแท่ง HTF หรือต่อแท่ง M1

ถ้าข้อใดไม่ผ่าน: **ห้ามเปิดใช้ MTF ในระบบเทรดจริง** และส่งผลกลับเพื่อออกแบบทางเลือกใน Task ถัดไป
